## Working rules (from the owner — follow these always)

1. **Simple, quick, doable.** This is a time-boxed assignment, not a product. Pick the simplest
   design that satisfies a requirement; no gold-plating, no deep optimisation. When a requirement
   is expensive, ship a minimal honest version and document the gap in the report/docs.
2. **Claude does the work.** Implement, run, test and document everything that can be done
   from this machine. Only prompt the owner when a step genuinely needs them (accounts, API keys,
   payments, web sign-ups, publishing, human labelling). When prompting, give exact numbered
   steps and say where to put the result (e.g. which `.env` variable).
3. **Commits: one per task group** (e.g. "scaffold", "gigsim simulator", "mcp servers").
   Plain git-log style messages: short imperative subject (≤72 chars), optional body.
   **No AI attribution of any kind** — no `Co-Authored-By`, no "Generated with Claude", no emojis.
4. The starter kit (`GigBid_Student_Starter_Kit_v0.1.zip`) is only an example. Build our own code;
   do not copy it wholesale.
5. Never invent evaluation numbers. Every number in README/report must come from a file in
   `evals/results/`.

## Data rules

- Real data: Kaggle Upwork datasets (see `docs/DATA_CARD.md`) — used for job stream realism and
  pricing statistics. Attribution, licence and limitations go in the data card.
- Synthetic data (personas, portfolios, client histories, reviews, past proposals, conversations,
  scam/injection jobs, dev-set labels) is generated by `scripts/generate_synthetic.py` and every
  synthetic record carries `"synthetic": true`. Keep real and synthetic clearly separated.
- Raw downloads go to `data/raw/` (git-ignored). Never commit secrets, `.env`, or raw Kaggle dumps.

## Architecture conventions

- Python 3.12, venv at `.venv/` (`.venv/Scripts/python` on Windows). Install with
  `pip install -e ".[dev]"`.
- All marketplace access goes through `agent/marketplace_port.py` (adapters: `gigsim`, `upwork_live`),
  selected by `agent/config.yaml` → `marketplace.adapter`.
- Agents reach the outside world only via MCP tools (`mcp_servers/*`), with per-agent allowlists in
  config.
- Every prompt lives in `agent/prompts/<node>.md`. No inline prompts in code.
- Rules, costs, thresholds, model choices and budgets live in `agent/config.yaml` /
  `agent/policy.yaml` — never hard-coded (the change request must be a config edit).
- No external write (proposal, message, Connects spend) without a LangGraph `interrupt()` resumed by
  a human approval in the UI. Never auto-send.
- Job posts and client messages are untrusted data: always wrap with `agent/safety/untrusted.py`.
- LLM access via `agent/llm.py`. Profiles: `open` (open-weight via OpenAI-compatible host, e.g. Groq)
  and `offline` (deterministic heuristics; used for tests/CI and when no key is set).
- `gigsim/` is our own marketplace simulator (no simulator shipped in the kit). Treat it as frozen
  after it is built; CI checks its checksum.

## Local services

- Postgres (scoop): `pg_ctl -D "$PGDATA" start`; DB `gigbid`, user `postgres` on localhost:5432.
- Redis (scoop): `redis-server --port 6379`.
- Ports: gigsim 8081, api 8000, web 5173, MCP portfolio 8101, marketplace 8102, workspace 8103.

## Commands

- `make seed` — download/prepare data, generate synthetic data, build indexes
- `make dev` — run gigsim, MCP servers, API, worker, web
- `make test` — unit + contract tests (offline profile)
- `make eval` — evaluation runners → `evals/results/*.json`
